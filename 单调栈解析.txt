# next_greater_stack.cpp 解析（下一个更大元素 · 单调栈）

## 一、先认清这份代码的「口径」

看代码之前必须先固定三件事，否则后面全是误会：

| 项目 | 本代码的口径 | 常见「另一种写法」 |
|---|---|---|
| 下标 | **1 基**，`a[1..n]`，`a[0]` 弃用 | 0 基 `a[0..n-1]` |
| 答案含义 | **位置**（1 基下标） | 值 |
| 无解 | **0** | -1 |
| 比较符号 | `a[top] < a[i]`，即**严格更大**才出栈 | 可能用 `<=`（非严格） |

所以输出的是「右边第一个更大元素的**下标**」，不是那个更大的值。
如果题目要的是值，第 19 行应改成 `f[st.back()] = a[i];`。
**先确认题目要位置还是要值，这是最容易错的地方。**

## 二、代码逐段说明

```cpp
long long n;
if (!(cin >> n) || n <= 0) return 0;   // 读入元素个数，非法输入直接退出

vector<long long> a(n + 1);            // a[1..n] 存数据，a[0] 弃用
vector<int> f(n + 1, 0);               // f[i]: a[i] 右边第一个更大元素的位置(1基)，无则0
vector<int> st;                        // 单调栈，存下标；对应值从栈底到栈顶严格递减

for (long long i = 1; i <= n; i++) {   // 读入 n 个数到 a[1..n]
    cin >> a[i];
}
```

- `vector<int> st` 就是**用 vector 手写的栈**：`st.back()` 相当于 `top()`，`push_back` 相当于 `push`，`pop_back` 相当于 `pop`。功能上和 `std::stack` 等价，只是能随机访问、常数更小。
- `f` 初始化为 0，表示「暂时还没有答案」。循环结束后仍然是 0 的，就是「右边没有更大的值」。
- `a[0]` 虽然不存数据，但它的 0 值不会被读进循环（循环从 1 开始），所以没有副作用。

```cpp
for (long long i = 1; i <= n; i++) {   // 从左到右扫描每个元素
    while (!st.empty() && a[st.back()] < a[i]) {
        f[st.back()] = (int)i;         // a[i] 就是栈顶元素右边第一个更大的值
        st.pop_back();                 // 该元素答案已确定，弹出
    }
    st.push_back((int)i);              // 当前元素入栈，等待将来被更大的值弹掉
}
```

只有两件事：

1. **`while` 结算**：栈里存的是「还在等答案」的下标。只要栈顶那个元素 `a[st.back()] < a[i]`，说明 `i` 就是它右边第一个更大的位置 → 写下 `f[st.back()] = i`，然后弹掉。这个动作可能连续发生很多次（可能一次清掉一整串）。
2. **`push_back(i)`**：结算完，当前元素自己也入栈等答案。**每一轮无条件执行一次**，这是栈里元素唯一的来源。

### 「`while` 里没有 `i++`，为什么还能执行多次？」

这是最容易卡住的一点，关键在于：**决定 `while` 循环次数的不是 `i`，而是 `st`（栈）**。

`while` 每一圈结束时都会**重新求值条件**：

```cpp
while (!st.empty() && a[st.back()] < a[i]) { ... }
//                    ↑ 每次都会重新读一次 st.back()
```

而循环体里的 `st.pop_back()` 会**把 `st.back()` 换成一个新的值**。于是下一圈条件里的：
- `st.empty()` 可能由假变真；
- `a[st.back()]` 也可能由小变大。

条件一变，循环就可能继续或停止——**循环变量是"栈顶是谁"，不是 `i`**。所以这三行虽然没写出任何 `++`，状态却在圈与圈之间被 `pop_back()` 改掉了。

用 `a = [2, 1, 4, 3]`、`i = 3` 这一轮实测：

| 第几圈 | 条件 `a[st.back()] < a[i]` | 求值结果 | 循环体做了什么 | 圈末栈 |
|---|---|---|---|---|
| 第 1 圈 | `st.back()=2` → `a[2]=1 < 4` | 真 | `f[2]=3`，`pop_back()` | `[1]` |
| 第 2 圈 | `st.back()=1` → `a[1]=2 < 4` | 真（**因为栈变了，条件重新算，不再是上一圈的 `2<1`**） | `f[1]=3`，`pop_back()` | `[]` |
| 第 3 圈 | `st.empty()` 为真 | 假 | 不进入，循环结束 | `[]` |

同样是 `i=3`，`while` 跑了 2 圈。因为第 1 圈把 `st.back()` 从 `2` 换成了 `1`，第 2 圈读到的就是另一个元素。

注意对比：**`i` 的推进是外层 `for` 的 `i++` 负责的，`while` 根本不负责推进 `i`。** 两层循环分工不同：

- `for`：决定"现在拿谁来当买家"，一轮一个下标。
- `while`：这个买家能买几个，取决于货架上（栈里）有多少人比它矮。

### 为什么必须写 `while` 而不是 `if`

`if` 只算一次条件、只弹一个。那 `a=[2,1,4,3]` 走到 `i=3` 时只会弹掉 `2`（`f[2]=3`），`1` 就留在栈里被 `4` 盖住了——但 `1` 的答案明明是位置 3，却被漏掉。

实测：把 `while` 改成 `if`，输出会从正确的 `3 3 0 0` 变成错的 `0 3 0 0`（`f[1]` 再也没机会被赋值）。

一句话：**`while` 保证"新来的人把所有能被它结清的人一次结清"；`if` 只结清一个，会漏。**

## 三、栈里元素从哪来

这是最常卡住的点。答案：**全部来自第 22 行的 `st.push_back(i)`，每轮一次，没有别的来源。**

- `st` 声明在循环**外面**，所以跨轮存活。
- 第 1 轮之前栈是空的；`i = 1` 时 `!st.empty()` 为假，`while` 直接跳过，然后 `push_back(1)`——栈里就有了第一个元素。

### 逐轮演示：`a = [2, 1, 4, 3]`（1 基）

*************重点能看懂的地方：| `i` | `a[i]` | `while` 判断过程 | 出栈并写 `f` | `push` 后栈（底→顶） | 栈对应值 |
|---|---|---|---|---|---|
| 1 | 2 | 栈空，跳过 | — | `[1]` | `[2]` |
| 2 | 1 | `a[1]=2 < 1`？假 | — | `[1, 2]` | `[2, 1]` |
| 3 | 4 | `a[2]=1 < 4`？真 → `f[2]=3`，弹；`a[1]=2 < 4`？真 → `f[1]=3`，弹；栈空，退出 | 2, 1 都得到 3 | `[3]` | `[4]` |
| 4 | 3 | `a[3]=4 < 3`？假 | — | `[3, 4]` | `[4, 3]` |

循环结束后 `f[3] = f[4] = 0`。

输出：`3 3 0 0`

含义：`a[1]=2` 右边第一个更大的是 `a[3]=4`（位置 3）；`a[2]=1` 同理；`a[3]=4`、`a[4]=3` 右边没有更大的。

第 3 轮就是所谓「一次性结清」：新来的 4 把前面寄存的 1 和 2 全部买断，它们共享同一个答案位置 3。

### 每个元素的生命周期

| 下标 | 何时进栈 | 何时出栈 | 在栈里待了几轮 |
|---|---|---|---|
| 1 | i=1 的 `push` | i=3 的 `push` 前被 `while` 弹掉 | 2 |
| 2 | i=2 的 `push` | i=3 的 `push` 前被 `while` 弹掉 | 1 |
| 3 | i=3 的 `push` | 循环结束仍在栈里 | — |
| 4 | i=4 的 `push` | 循环结束仍在栈里 | — |

**每个元素最多进栈一次、出栈一次**，所以 `while` 的全部弹出次数不超过 n，总复杂度 **O(n)**，空间 O(n)。

### 如果 `while` 一圈都不执行，会怎样？

**完全不会怎样。** `while` 不是必跑的步骤，它只是"能结清就顺手结清"的优化动作。跳过它的那一轮只有两个后果：

1. 没有任何 `f[...]` 被赋值 → 栈里那些人的答案**暂时**还是 0，**不是"没有答案"**，只是"还没等到"；
2. 当前元素照常 `push_back(i)` 进栈，继续排队。

`while` 不执行只有两种情形：

| 情形 | 条件为假的哪一半 | 例子 | 含义 |
|---|---|---|---|
| 栈是空的 | `!st.empty()` 假 | `i=1`（第一轮） | 前面没有任何人在等答案，没人可结清 |
| 栈非空但栈顶不小 | `a[st.back()] < a[i]` 假，即 `a[st.back()] >= a[i]` | `a=[2,1,...]` 的 `i=2`；`a=[2,1,4,3]` 的 `i=4` | 栈顶那位**还没等到**自己的更大值，而且它比 `a[i]` 大或相等，会一直挡在栈上 |

第二种情形正是**单调栈能成立的关键**：栈顶元素比 `a[i]` 大，说明新来的 `a[i]` 既救不了它（不够大），也救不了它下面的任何人——因为下面的人只会更大。所以栈里剩下的全部保持"继续等"，无需做任何事。

**不要和漏答案混淆**：

- `while` 不执行 → 答案**暂时**为 0，后面还会被更大的值填上；
- 循环全部结束仍是 0 → 答案**真的**不存在（右侧确实没有更大的）。

`a = [2, 1, 4, 3]` 里，`i = 2` 和 `i = 4` 两轮 `while` 都没跑，但 `f[1]、f[2]` 在 `i=3` 那轮就被填成了 3；而 `f[3]、f[4]` 直到程序结束都是 0，这才是"无解"。同一个 0，出现的位置不同，含义完全不同。

**如果整段程序里 `while` 一次都没跑**（比如 `a = [5, 4, 3, 2, 1]` 严格递减）：每轮都只做 `push_back`，栈变成 `[1, 2, 3, 4, 5]`，容量就是 n，输出全 0。这是合法的正确答案——每个元素右边都没有更大的值。此时时间复杂度是 O(n)，但 `while` 一行都没执行，**这正说明复杂度不是靠 `while` 跑出来的，是靠"总弹出次数 ≤ n"摊销出来的**。

## 四、两条核心性质（为什么可以「就地出栈」）

1. **答案在「第一次被满足」的瞬间就定案。**
   题目要的是「右边**第一个**更大的」，而 `i` 从左往右扫描，遇到满足条件的位置的先后顺序天然就是从近到远。所以一旦 `a[i]` 满足栈顶条件，`i` 就是它的最终答案，不必再往后比较、也不可能被后面更大的值改写。

2. **栈内自底向顶不会递增。**
   若栈里 `k` 在 `i` 下面（`k` 更早入栈），说明 `k` 还没等到答案，即 `a[j] <= a[k]` 对所有已扫过的 `j`（在 `k` 之后）成立，包含 `a[i]`。所以 `a[k] >= a[i]`——下面的元素一定不比上面小。这就是「单调栈」名字的来源，也是新来的 `a[i]` 只需要和栈顶比较、而不用管整栈的原因。

> ⚠️ 第 11 行注释写的是「严格递减」，在使用 `<`（严格更大才出栈）时**并不准确**：相等的值不会被弹掉，可以共存于栈中。例如 `a = [3, 3]`，`i=2` 时 `a[1]=3 < 3` 为假，不下栈，栈变成 `[1, 2]`，值为 `3, 3`。
> 准确的说法是「**非递增**（单调不增）」。如果想让栈严格递减，比较应写成 `a[st.back()] <= a[i]`，但那同时会把题目语义变成「右边第一个大于或等于的位置」。

## 五、`>` 还是 `>=`：这一步决定题目语义

| 写法 | 语义 | 栈的单调性 | 例子 `a=[3,3,4]` 的结果 |
|---|---|---|---|
| `a[st.back()] < a[i]`（当前代码） | 右边第一个**严格更大** | 非递增 | `f = [3, 3, 0]` |
| `a[st.back()] <= a[i]` | 右边第一个**大于或等于** | 严格递减 | `f = [2, 2, 0]`→ 需要重新推演 |

（`a=[3,3,4]` 用当前代码：`i=1` push；`i=2` 3<3 假，push；`i=3` `a[2]=3<4` 真 → `f[2]=3`，弹；`a[1]=3<4` 真 → `f[1]=3`，弹；结果 `3 3 0`。）

**别把两者的结果混着记，先读题确定「严格」还是「非严格」。**

## 六、常见易错点清单

1. **答案要位置还是要值**：要值就把 `f[st.back()] = (int)i` 改成 `f[st.back()] = a[i]`。
2. **无解标记要与初始化一致**：这里 `f` 初始化为 0，无解输出 0。若题面要求输出 -1，需在输出时转换或把初始化/输出改掉。
3. **`while` 写成 `if`**：会导致一大串元素只结算一个，答案错。
4. **忘了判空**：`a[st.back()]` 在空栈上访问是未定义行为，`!st.empty()` 必须放在 `&&` 左边（短路求值）。
5. **`<` 与 `<=` 选错**：见上一节，直接决定相等元素算不算答案。
6. **下标基准混用**：本代码 1 基，读入时从 `a[1]` 开始；若改成 0 基，输出边界 `i < n` 的空格处理也要跟着改。
7. **输出格式**：第 27 行 `if (i < n) cout << " ";` 是为了避免行尾多余空格，改成 0 基时要同步调整。
8. **复杂度直觉**：看到双层循环就以为是 O(n²)，但内层 `pop` 的总次数受「每元素只出栈一次」约束，整体是 O(n)。

## 七、一句话总结

`st` 是「候诊室」，`push` 让每个下标进来等答案，新来的 `a[i]` 一旦比栈顶大就把栈顶的答案写成 `i` 并赶走它——**答案是「第一个」满足条件的，栈的单调性保证只需比栈顶**，每个元素进出各一次，所以是 O(n)。
